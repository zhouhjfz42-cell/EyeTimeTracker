# 儿童控制商业版第一阶段合规底稿

更新时间：2026-07-08

状态：内部工作稿。本文不是最终隐私政策、用户协议或法律意见，只用于提前约束产品范围、数据设计、权限说明和上架准备。正式发布前需要按实际功能、第三方服务、服务器部署、支付方案和应用商店要求重新核对。

## 适用范围

本底稿面向 EyeTimeTracker 中文版儿童控制商业版。

当前产品策略：

- Android 手机和平板作为第一完整平台。
- 鸿蒙手机和平板纳入规划，Android 核心版跑通后再验证。
- iOS 和 iPadOS 只承诺按平台能力做降级版本，不提前承诺 Android 同等控制能力。
- Windows PC 继续作为个人用眼统计和同步伴侣，不作为儿童控制主平台。
- 海外英文版后置，先把中文版儿童控制商业版跑通。

## 基本原则

1. 只收集儿童控制和家长管理确实需要的数据。
2. 能用汇总数据解决的问题，不上传更细的原始数据。
3. 涉及孩子的数据，默认按更高保护标准处理。
4. 家长同意必须是明确操作，不能用默认勾选或关闭弹窗替代。
5. 每个敏感权限在申请前都要解释用途。
6. 默认不接广告，避免儿童场景下的广告和跟踪风险。
7. 不默认使用无障碍服务。只有 Android 核心控制能力确实无法实现时，才单独评估。
8. 登录、支付、后台、官网、权限系统优先复用已购买模板和成熟开源库，不从零开始写。

## 已确认产品和合规决策

- 上架主体：公司主体。
- 首发渠道：国内应用市场。
- 中国版服务器：使用境内服务器。
- 广告：首版明确不接广告。
- 儿童范围：低于 18 岁。
- 孩子档案：首版必填项只保留昵称，其余信息由家长自愿填写。
- 免费试用：全功能试用，试用期暂定 3 天或 1 周，后续结合转化和家长决策周期再定。
- 家长网页后台：暂不需要。
- 登录方式：中国版短信登录和微信登录为必选，邮箱登录可选。Apple 登录跟 iOS 版一起考虑。
- 支付方式：中国版首选内置微信支付和支付宝支付。
- 学校或机构场景：暂不预留专门入口。

中国版使用境内服务器的原因：

- 避免首版默认产生个人信息跨境传输问题。
- 方便后续办理 APP 备案、网站备案、域名和云服务相关材料。
- 方便与国内短信、微信登录、微信支付、支付宝支付、推送和客服系统衔接。
- 降低国内应用市场审核时对数据存储、儿童数据和第三方服务的解释成本。
- 提高国内家庭访问速度和稳定性。

## 数据清单草案

| 数据类型 | 示例 | 用途 | 是否上传服务器 | 初步风险判断 |
| --- | --- | --- | --- | --- |
| 家长账号 | 手机号、邮箱、密码散列、登录令牌 | 登录、找回账号、管理家庭 | 是 | 个人信息 |
| 家庭空间 | 家庭 ID、成员角色、邀请关系 | 绑定家长和孩子设备 | 是 | 个人信息 |
| 孩子档案 | 必填：昵称。可选：年龄段、头像、与家长关系 | 展示和区分孩子设备 | 是 | 儿童个人信息，首版应只强制昵称 |
| 设备绑定 | 设备 ID、平台、型号、系统版本、App 版本、推送令牌 | 识别孩子设备、同步规则和提醒 | 是 | 个人信息 |
| App 使用记录 | 包名、App 名称、类别、开始时间、结束时间、累计时长 | 统计和限制具体 App 使用 | 是，首版可先限制保留周期 | 敏感，Google Play 将应用列表和使用数据视为敏感数据 |
| 屏幕使用汇总 | 今日、本周、本月总时长，夜间用眼，连续使用段 | 报告和健康建议 | 是 | 个人信息 |
| 家长规则 | 每日总时长、App 限额、夜间规则、休息规则 | 控制孩子设备 | 是 | 家庭管理数据 |
| 家长操作记录 | 批准延长、拒绝延长、解除限制、修改规则 | 追溯规则变化，减少误解 | 是 | 个人信息 |
| 会员和订单 | 套餐、订单号、微信或支付宝交易标识、支付渠道、到期时间、退款状态 | 商业化和客服 | 是 | 支付相关信息，不保存银行卡号 |
| 异常和诊断 | App 版本、错误类型、设备诊断信息 | 修复崩溃和兼容问题 | 是，可关闭或最小化 | 需要避免包含孩子内容 |
| 通知数据 | 推送令牌、提醒类型、发送状态 | 家长提醒和孩子提醒 | 是 | 个人信息 |

首版明确不收集：

- 通讯录。
- 短信和通话记录。
- 精确位置。
- 相册、照片、视频。
- 摄像头和麦克风内容。
- 聊天内容、浏览内容、输入内容。
- 生物识别信息。
- 身份证号等强身份信息，除非未来法律或支付流程确实要求。

## 权限说明草案

| 权限或系统能力 | 使用场景 | 首版建议 |
| --- | --- | --- |
| 使用情况访问权限 | 读取孩子设备上各 App 的使用时间 | Android 儿童控制核心功能，需要清晰引导家长手动开启 |
| 通知权限 | 提醒孩子休息，通知家长规则和异常 | 需要 |
| 前台服务和后台运行 | 保持统计、规则检查和提醒可靠 | 需要，同时说明耗电影响 |
| 开机启动 | 设备重启后继续保护规则 | 建议需要 |
| 悬浮窗或覆盖显示 | 在限制 App 时显示提醒或限制页 | 谨慎使用，优先考虑普通页面方案 |
| 网络访问 | 账号、家庭、规则、报告和支付同步 | 需要 |
| 应用列表或包名读取 | 建立 App 限制规则和分类 | 尽量只读取必要信息 |
| 无障碍服务 | 可能用于更强控制或判断前台 App | 不作为首版默认方案，风险高，需要单独评估和说明 |

Android 的使用情况访问权限需要用户到系统设置中授权。这个权限不会像普通权限一样只弹一个系统确认框，所以产品里必须有一步清楚解释“为什么需要、开启后会看到什么、不开启会缺失什么”。

无障碍服务要特别谨慎。Google Play 对无障碍 API 有单独政策和声明要求，核心用途应服务于残障用户辅助。如果未来为了儿童控制考虑使用，必须单独做合规评估、用户披露、商店声明和演示视频，不能悄悄接入。

## 家长同意流程草案

建议首版流程：

1. 家长安装应用并创建账号。
2. 家长阅读隐私说明、儿童数据说明和服务规则。
3. 家长用明确按钮同意后，创建孩子档案。首版只要求填写昵称，年龄段、头像、与家长关系等信息由家长自行选择是否设置。
4. 家长在孩子手机或平板上安装儿童端。
5. 通过配对码或二维码绑定孩子设备。
6. 孩子设备上显示“本设备由家长管理”，并展示主要规则。
7. 逐项引导开启使用情况访问、通知、后台运行等权限。
8. 家长设置每日总时长、App 限制和夜间规则。
9. 家长可在账号中删除孩子档案、解绑设备、导出或删除数据。
10. 首版中国区账号体系优先支持短信登录和微信登录。

不能用以下方式替代同意：

- 默认勾选隐私政策。
- 只展示一段文字但没有确认按钮。
- 关闭弹窗即视为同意。
- 孩子单独同意后就开始上传数据。

如果孩子和家长共用一台设备，需要在产品内明确提示：开启儿童控制后，设备上相关 App 使用记录可能被统计进孩子报告。

## 平台能力边界

| 平台 | 首版定位 | 可期待能力 | 主要风险 |
| --- | --- | --- | --- |
| Android 手机和平板 | 第一完整平台 | App 使用统计、每日限额、App 限额、夜间规则、提醒、家长报告 | 权限开启复杂，不同品牌后台限制不同，应用商店审核关注数据和权限用途 |
| 鸿蒙手机和平板 | 后续验证 | 需验证能否稳定读取 App 使用和显示限制页 | 权限模型、应用市场审核、原生开发成本不确定 |
| iPhone 和 iPad | 降级平台 | 需验证 Screen Time、FamilyControls、DeviceActivity、ManagedSettings 等能力 | Apple 平台权限和商业化限制更强，不能提前承诺完整控制 |
| Windows PC | 统计伴侣 | 本地统计、提醒、与手机同步 | 不作为儿童控制主平台 |

## 审核和合规风险清单

1. 儿童数据风险：面向儿童或涉及未成年人数据时，需要更清晰的家长同意、数据删除和最小化收集机制。
2. App 使用数据风险：Google Play 将应用列表和使用数据纳入敏感范围，需要在隐私政策和数据安全表中准确披露。
3. 后台收集风险：后台统计和上传必须有明显说明，不能让用户误以为只在打开 App 时统计。
4. 无障碍服务风险：不适合作为默认方案，若使用需要单独申报和解释。
5. 悬浮窗和限制页风险：体验上容易被认为打扰用户，需要可解释、可关闭、可由家长管理。
6. 广告风险：儿童产品首版建议不接广告。若未来接广告，需要使用符合儿童政策的广告方案。
7. 支付风险：中国版首选内置微信支付和支付宝支付。会员、退款、自动续费和未成年人消费要提前设计，不要最后补。
8. 账号删除风险：如果支持创建账号，就要提供账号和相关数据删除路径。
9. 第三方 SDK 风险：模板、登录、支付、推送、崩溃上报、统计 SDK 都要纳入数据清单。
10. 国内上架风险：隐私政策、用户协议、儿童个人信息规则、ICP备案、APP 备案、软著或主体材料等需要提前准备。
11. 跨境传输风险：中国版已确定使用境内服务器。如果未来接入海外 SDK 或海外版账号体系，需要另行评估。

## 数据保留草案

这是工作建议，正式周期需要结合服务器成本、用户价值、法规和商店要求再定。

| 数据 | 建议保留 |
| --- | --- |
| 原始 App 使用明细 | 30 到 90 天，优先短周期 |
| 每日汇总和趋势 | 1 到 2 年，供家长查看长期趋势 |
| 家庭、孩子、设备资料 | 账号有效期间保留，删除账号或孩子档案时删除 |
| 家长操作记录 | 180 天到 1 年，用于解释规则变化和客服 |
| 崩溃和诊断日志 | 90 天以内 |
| 订单和会员记录 | 按支付、税务、客服要求保留，正式发布前再确认 |

删除要求：

- 家长应能删除孩子档案。
- 家长应能解绑孩子设备。
- 家长应能删除账号。
- 删除后应停止继续上传该孩子设备数据。
- 如果因订单、税务或争议处理需要保留部分记录，应在正式隐私政策中说明。
