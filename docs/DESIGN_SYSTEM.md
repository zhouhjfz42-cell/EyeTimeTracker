# 用眼时间设计规范手册

这份规范用于 EyeTimeTracker 及后续同系列 App。目标不是做强品牌化视觉，而是形成一种安静、可信、低摩擦的健康工具气质：打开就能看懂，长期使用不吵，关键数据足够醒目。

## 设计性格

产品应像一个克制的健康仪表盘，而不是营销页、游戏页或系统设置页。

- 信息优先：首屏先显示用户最关心的当前状态和关键数字。
- 低装饰：不使用渐变大背景、装饰光斑、复杂插画或无意义的卡片堆叠。
- 轻情绪：用绿色传达正常和可控，用黄色提示偏高，用红色提示风险，但避免恐吓式表达。
- 稳定：同类信息永远放在相似位置，按钮、卡片、弹窗使用一致形状。
- 面向普通用户：界面文案只说用户需要知道的事，不出现“后续版本”“本轮暂不包含”“后台补齐”等开发者语言。

### 基础色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#F8FCFA` | App 主背景，略带绿色，避免纯白刺眼。 |
| 桌面/外层背景 | `#F5F7F8` | mockup、PC 窗口外层或页面外背景。 |
| 面板背景 | `#FCFEFD` | 统计卡、弹窗、主内容面板。 |
| 卡片浅底 | `#EEF9F5` | 指标卡、次级状态卡。 |
| 线框 | `#D9EEE7` | 卡片描边、分割线、轻按钮边界。 |
| 更淡线框 | `#DFF0E9` | 大面积面板边界或柔和分割。 |

### 品牌与状态色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 主绿色 | `#16A67D` | 主按钮、正在统计、主数字、安全状态。 |
| 深绿色 | `#118866` | 按下态、强调态、深色小标签。 |
| 蓝紫色 | `#5B5CE2` | 手机数据、第二来源数据、对比图表。 |
| App 排行蓝 | `#4285F4` | 排行条、应用来源图标的一类颜色。 |
| 黄色提醒 | `#F0B83A` | 最长连续、偏高、需要关注但不紧急。 |
| 红色风险 | `#E96868` | 超限、危险、删除或退出家庭护眼。 |

### 文字色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 一级文字 | `#111827` | 标题、关键值、按钮文字。 |
| 二级文字 | `#657289` 或 `#667085` | 标签、说明、状态描述。 |
| 弱文字 | `#8E94A0` | 时间、更新时间、低权重辅助信息。 |
| 禁用文字 | `#98A2B3` | 不可用按钮、未开启状态。 |
| 反白文字 | `#FFFFFF` | 主按钮、深色图标文字。 |

### 使用规则

- 绿色只用于“可行动、正在运行、健康主状态”，不要把整页染成绿色。
- 蓝紫只用于“手机来源、第二数据来源、对比数据”，不要与主按钮争抢。
- 红色只用于明确风险或危险动作，例如退出、删除、不可恢复。
- 大面积背景只用浅色，不用高饱和色块。
- 同屏不要超过 1 个主色焦点，通常是主数字或主按钮。

## 字体

### 字体族

优先使用：

```text
Noto Sans SC
```

系统回退：

```text
Microsoft YaHei UI, Microsoft YaHei, PingFang SC, Segoe UI, system-ui, sans-serif
```

PC 端优先内置或加载 `Noto Sans SC`，Android 端使用系统中文无衬线字体即可。不要使用宋体、仿宋、楷体或装饰字体。

### 字重

| 用途 | 建议字重 |
| --- | --- |
| 大标题、主数字 | `800-840` |
| 卡片标题、按钮 | `760-820` |
| 普通正文 | `500-650` |
| 说明文字 | `450-600` |

避免全屏大量使用超粗黑体。App 排行、列表项名称可以适当减轻字重，防止拥挤和遮挡。

## 布局

### 页面结构

移动端页面优先使用以下顺序：

1. 状态栏和顶部导航。
2. 页面标题。
3. 当前对象和状态，例如“今天 · 统计中”或“木木 · 家长手机”。
4. 主数字。
5. 轻提示或更新时间。
6. 2x2 关键指标卡。
7. 主操作按钮。
8. 说明文字或次级内容。

统计页优先使用：

1. 标题和说明。
2. 单日情况。
3. App 使用排行。
4. 周/月趋势。
5. 护眼摘要。

### 间距

- 页面左右边距：移动端 `24dp` 左右，PC 端 `24-32px`。
- 大区块间距：`24-32dp`。
- 卡片内边距：移动端 `18-24dp`，PC 端 `16-22px`。
- 列表项垂直间距：移动端 `18-24dp`，PC 端 `10-16px`。
- 标题与副标题间距：`8-12dp`。

### 对齐

- 首页主数字左对齐，保持仪表盘感。
- 状态提示可以居中，但不能挤占主数字。
- 卡片值和标签左对齐，减少扫视成本。
- App 排行中，图标、来源图形、App 名称在左侧，时间在条形图上方或右侧，条形图尽量延伸到可用宽度。

## 组件

### 卡片

卡片是信息容器，不是装饰。

- 普通卡片背景：`#EEF9F5`。
- 统计面板背景：`#FCFEFD` 或白色。
- 描边：`1px #D9EEE7`。
- 移动端圆角：`18-24dp`。
- PC 端圆角：`16-22px`。
- 不要卡片套卡片。重复列表项可以是卡片，但页面分区不要做成层层浮动容器。

### 按钮

主按钮：

- 背景：`#16A67D`。
- 文字：白色。
- 圆角：胶囊形，`999dp`。
- 高度：移动端 `58-68dp`，PC 端 `40-52px`。
- 文案使用明确动作，如“统计页”“保存”“确认”。

次按钮：

- 背景：`#EEF9F5` 或 `#F0F3F4`。
- 文字：`#16A67D` 或 `#344054`。
- 用于取消、返回、低风险操作。

危险按钮：

- 文字或背景使用红色。
- 必须配合明确文案，例如“退出家庭护眼”。

### 状态点和来源标识

状态点：

- 在线/统计中：绿色圆点。
- 离线/未启用：灰色圆点。
- 状态点只表达状态，不单独作为按钮。

来源标识：

- PC 使用绿色电脑图形或绿色小标签。
- 手机使用蓝紫色手机图形或蓝紫小标签。
- 当空间紧张时，优先使用图形，少用“电脑/手机”文字标签。

### App 使用排行

App 排行用于替代低价值连续使用分析时，应保持高信息密度。

- 标题：`App 使用排行`。
- 每行包含来源图形、App 名称、时长、进度条。
- App 名称不要过粗，避免遮挡。
- 时长在空间紧张时使用 `14:02` 表示 14 小时 02 分；不足 1 小时可用 `26分`。
- 图标获取不稳定时，不强制显示真实图标，优先显示来源图形和 App 名称。
- 如果使用代替图标，只显示 App 名称首字，避免传输或保存大体积图标数据。

### 弹窗

弹窗必须使用 App 自定义样式，不使用系统默认样式，避免美术风格割裂。

- 背景：白色或 `#FCFEFD`。
- 圆角：`26-32dp`。
- 遮罩：黑色 45%-55% 透明。
- 标题：大而明确。
- 说明文字只讲用户结果，不讲技术实现。
- 按钮左右并列时：取消在左，确认在右。

## 图表

图表用于回答一个明确问题，不做装饰。

- PC 端 24H 环形热力图用于展示一天内分布。
- 电脑数据用绿色，手机数据用蓝紫。
- 趋势线用绿色，参考线可用浅黄色虚线。
- 柱状图底部标签必须留足空间，不能遮挡。
- 图表加载或切换时间时，只重绘被修改的区块，不带动整页闪动。

## 文案原则

### 可显示给用户的话

- “刚刚更新”
- “1分钟前更新”
- “孩子设备暂时没有响应”
- “禁用时段不会锁住手机。孩子设备会弹出休息提醒，并记录这段时间的用眼。”
- “需要修改孩子档案、保护密码或规则时，进入右上角设置。”

### 不应显示给用户的话

- “后续版本支持”
- “本轮暂不包含”
- “后台补齐详细统计”
- “云同步接入后更新”
- “开发中”
- “v1 scope”

### 文案风格

- 少用解释，多给结论。
- 不把内部实现暴露给用户。
- 不使用“强制管控”“监视”等压迫性词汇，优先使用“护眼”“提醒”“规则”“家庭设置”。
- 对儿童端提示要温和，对家长端提示要明确。

## 家庭护眼模式补充规则

家庭护眼不是另一个 App，而是同一 App 内的模式切换。因此视觉上要和个人版一致：

- 家长端和儿童端首页沿用个人版首页结构。
- 家长端右上角提供“设置”入口。
- 儿童端没有普通设置入口；修改家庭设置需要保护密码。
- 家庭首页的“更新时间/同步状态”放在主数字与指标卡之间，使用括号弱提示，例如“（刚刚更新）”。
- 家庭首页说明文案放在统计页按钮下方，和成人版说明位置一致。
- 家庭首页右下指标可显示“最长 App”，不要与规则设置里的提醒卡重复。

## 响应和性能

健康工具的“快”本身是设计的一部分。

- 点击后应立即有视觉反馈。
- 进入页面优先显示上次缓存数据，再后台刷新。
- 大统计数据应提前缓存，今天实时计算，历史日期读取缓存。
- 切换单个图表时间，只更新该图表。
- 不要因为 App 图标、完整统计、网络同步阻塞首页绘制。

## 设计检查清单

交付前逐项检查：

- 首屏是否能在 3 秒内让用户知道当前用眼状态。
- 页面是否有无意义空档。
- 文案是否有开发者语言。
- 主按钮是否唯一且明确。
- 同类设置是否放在同一个地方。
- 颜色是否只在表达状态和行动，不做装饰堆叠。
- 字体是否过粗导致拥挤。
- 文字是否被截断、换行或遮挡。
- 弹窗是否和 App 风格一致。
- 图表是否回答明确问题。
- 家庭端和个人端是否复用同一套视觉语言。
