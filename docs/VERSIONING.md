# 版本与数据标记

更新时间：2026-07-08

这份文档用于区分已经完成的个人成人版，以及下一阶段要开发的儿童控制商业版。后续大版本更迭时，不应把两条产品线的数据和概念混在一起。

## 当前基线版本

当前版本已经完成了个人成人版的核心闭环：

- Windows PC 本地用眼统计。
- Android 本地用眼统计。
- PC 与 Android WiFi 局域网配对同步。
- 双端使用统一 10 秒时间格合并统计，重叠时间只计算一次。
- 主界面和统计页展示合并后的统计结果。
- PC 与 Android 提醒。
- Android 横幅通知、声音和振动。
- PC 提醒声音。
- PC 系统托盘菜单。
- PC 开机启动开关。
- 多语言文案底座。

这个版本作为后续儿童控制商业版之前的个人成人版基线。

建议标记：

- 产品阶段：`personal`
- 版本代号：`personal-sync-baseline`
- Git 标签：`v0.9-personal-sync`

## 后续儿童控制版标记

儿童控制商业版不是直接覆盖个人成人版，而是下一代产品线。

建议从儿童控制版开始，在数据和同步协议中显式保存版本信息：

- `productMode`：产品模式。
- `dataSchemaVersion`：数据结构版本。
- `syncProtocolVersion`：同步协议版本。
- `clientVersion`：客户端版本。
- `deviceRole`：设备角色。

建议取值：

| 字段 | 个人成人版 | 儿童控制版 |
| --- | --- | --- |
| `productMode` | `personal` | `family_child_control` |
| `deviceRole` | `personal_device` / `pc_companion` | `parent_device` / `child_device` / `pc_companion` |
| `dataSchemaVersion` | `1` | 从 `2` 开始 |
| `syncProtocolVersion` | `1` | 需要变更时递增 |

## 数据迁移原则

- 个人成人版已有数据继续保留。
- 儿童控制版不要直接改写个人成人版历史数据。
- 如果未来同一应用内同时支持两种模式，界面上要明确当前模式。
- 儿童控制版的家庭、孩子档案、App 使用记录、规则、会员状态，应使用新的数据结构。
- 个人成人版本地记录可以作为参考数据，但不能默认变成孩子数据。

## 开发原则

- 进入儿童控制版代码开发前，先确认需要新增或修改哪些数据字段。
- 涉及本地数据、云同步、家庭账号、孩子档案、支付会员时，必须同时考虑版本字段。
- 如果数据结构变化影响旧版本读取，需要写清楚迁移方式。
- 如果旧数据无法完整迁移，应保留原始数据，不做静默丢弃。

## 当前状态

当前文档只是标记规则，不代表已经在代码中加入这些字段。

真正开始儿童控制版开发时，需要根据当时的功能范围，把这些字段落到本地数据库、同步协议和服务器数据结构中。
