# 版本与数据标记

更新时间：2026-07-08

这份文档用于区分已经完成的个人护眼模式基线，以及下一阶段要在同一 App 内增加的家庭护眼模式。后续大版本更迭时，不应把成人个人数据、家庭空间数据和孩子设备数据混在一起。

## 当前基线版本

当前版本已经完成了个人成人版的核心闭环：

- Windows PC 本地用眼统计。
- Android 本地用眼统计。
- PC 与 Android WiFi 局域网配对同步。
- 双端使用统一 10 秒时间格合并统计，重叠时间只计算一次。
- 主界面和统计页展示合并后的统计结果。
- PC 与 Android 提醒。
- Android 横幅通知、声音和振动。
- PC 提醒声音。
- PC 系统托盘菜单。
- PC 开机启动开关。
- 多语言文案底座。

这个版本作为后续商业版个人护眼模式的基线。家庭护眼模式应复用这套统计、提醒、同步和多语言基础，而不是另做一个独立 App。

建议标记：

- 产品阶段：`personal`
- 版本代号：`personal-sync-baseline`
- Git 标签：`v0.9-personal-sync`

## 后续商业版模式标记

商业版不是直接覆盖个人护眼模式，也不是拆成一个独立儿童 App，而是在同一 App 内增加家庭护眼模式。

建议从家庭护眼模式开始，在数据和同步协议中显式保存版本信息：

- `productMode`：产品模式。
- `dataSchemaVersion`：数据结构版本。
- `syncProtocolVersion`：同步协议版本。
- `clientVersion`：客户端版本。
- `deviceRole`：设备角色。

建议取值：

| 字段 | 个人护眼模式 | 家庭护眼模式 |
| --- | --- | --- |
| `productMode` | `personal` | `family` |
| `deviceRole` | `personal_device` / `pc_companion` | `parent_device` / `child_device` / `pc_companion` |
| `dataSchemaVersion` | `1` | 从 `2` 开始 |
| `syncProtocolVersion` | `1` | 需要变更时递增 |

## 数据迁移原则

- 个人护眼模式已有数据继续保留。
- 家庭护眼模式不要直接改写个人护眼模式历史数据。
- 如果未来同一应用内同时支持两种模式，界面上要明确当前模式。
- 家庭、孩子档案、App 使用记录、规则、会员状态，应使用新的数据结构。
- 个人护眼模式本地记录可以作为参考数据，但不能默认变成孩子数据。

## 开发原则

- 进入家庭护眼模式代码开发前，先确认需要新增或修改哪些数据字段。
- 涉及本地数据、云同步、家庭账号、孩子档案、支付会员时，必须同时考虑版本字段。
- 如果数据结构变化影响旧版本读取，需要写清楚迁移方式。
- 如果旧数据无法完整迁移，应保留原始数据，不做静默丢弃。

## 当前状态

当前文档只是标记规则，不代表已经在代码中加入这些字段。

真正开始家庭护眼模式开发时，需要根据当时的功能范围，把这些字段落到本地数据库、同步协议和服务器数据结构中。
